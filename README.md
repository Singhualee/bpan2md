# bpan2md —— 百度网盘分享链接 → 云端转写 → 知识库用 Markdown

把百度网盘的音视频（**或者你本机上已有的视频**）批量转成带时间戳、带元数据的 Markdown，直接丢进本地知识库。

```
分享链接  →  转存到自己网盘  →  下载到本机  ┐
                                          ├→  抽音频(ffmpeg)  →  上传公网  →  云端转写  →  Markdown + 分块 JSONL
本机已有的文件（文件夹扫描 / 上传）────────┘
```

两条路共用后面全部环节。**不让脚本下载**那条路（用网盘客户端自己下到本地，再让工具直接读）在本机限速严重时往往快一个数量级，而且完全不需要百度 Cookie。

## 从这里开始（三步）

### 方式一：网页界面（推荐，不用敲命令）

**双击 `启动网页.bat`**（macOS / Linux 是 `start_web.sh`）。

首次运行它会自动建好环境、装好依赖，然后打开浏览器。之后就是在这个页面里操作：

| 标签页 | 干什么 |
|---|---|
| **① 设置** | 把百度 Cookie、转写服务的 Key、对象存储的信息填进表单，点「保存设置」 |
| **② 先测一测** | 三个按钮：环境自检 → 网络与存储预检 → 云端链路体检。都不碰百度网盘，第三个约 0.001 元 |
| **③ 开始转写** | 把分享链接**整段**粘进大文本框（粘完立刻显示"认出了几个链接"）；同一个页面下方还有「直接转本机文件」：粘贴文件夹路径扫描，或者把文件拖进来 |
| **④ 结果** | 列出产出的 Markdown，点开看、点下载；一个按钮生成知识库索引；还有一张「磁盘占用与清理」表，可以一键把中间文件清掉 |

**每个要填的东西下面都有「怎么拿到？」**，点开就是逐步操作 + 直达控制台的按钮，不用去翻文档：

- **百度 Cookie**：F12 → Network → 刷新 → 找 Cookie 那一行 → 整段复制。
  ⚠️ 只走「本机文件」这条路的话，**这一项可以不填**
- **百炼 API Key**：[直达 API-KEY 页面](https://bailian.console.aliyun.com/cn-beijing/model/settings/api-key)。
  ⚠️ 注意右上角的**地域要和对象存储一致**，各地域的 Key 不能混用
- **OSS Bucket**：[直达 Bucket 列表](https://oss.console.aliyun.com/bucket) → 创建 →
  **地域选「华北2（北京）」，创建后不能改** → 名称全局唯一
- **AccessKey**：[直达 RAM 用户](https://ram.console.aliyun.com/users) → 创建用户 →
  权限管理里**必须授予 `AliyunOSSFullAccess`**（漏了会报没权限）
  ⚠️ **AccessKey Secret 只在创建时完整显示一次**，关掉弹窗就再也看不到
- **文件夹路径**：资源管理器里进到那个文件夹 → 点一下顶部**地址栏** → `Ctrl+C` → 粘进输入框

页面底部有实时进度日志，随时能「停止」。**关掉那个黑窗口就是退出程序。**

网页默认只监听本机（`127.0.0.1`），别人访问不到；所有密钥只写进你自己电脑上的 `.env`，界面上不会回显。服务还会拒绝非本机来源的请求（Host / Origin 校验），所以你在别的网页上时，那些页面无法偷偷指挥这个工具读你的文件或花你的钱。

### 方式二：命令行

```bash
# 1) 进到项目目录（run.py 在这里，不在上一层）
cd E:\音视频转写成文本-DSH\bpan2md

# 2) 建虚拟环境并装依赖（只需要 requests）
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt

# 3) 自检
python run.py check
```

装好之后先跑这两条（免费、不碰百度账号）：

```bash
python run.py preflight    # 查网络、OSS 桶名与地域
python run.py doctor       # 用 20 秒测试音频把云端链路真跑一遍
```

**三个常见坑：**

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `can't open file 'run.py': No such file or directory` | 你还在上层目录 | 先 `cd bpan2md`；或者不 cd，写全路径：`python bpan2md\run.py check` |
| `ModuleNotFoundError: No module named 'requests'` | 你那个 `python` 没装依赖 | 系统里常有多个 Python。用第 2 步的虚拟环境，或把解释器写全，例如 `D:\...\python.exe run.py check` |
| `SyntaxError: invalid syntax`（在 `>>>` 后面敲的） | 那是 Python 交互提示符，不是命令行 | 按 `Ctrl+Z` 再回车退出，回到正常的命令行提示符 |

`run.py` 会检查依赖并给出上面这些提示，不会只甩一段 traceback；它还会打印**当前用的是哪个 Python**，方便你对号入座。

## 一、先看清楚一件事：唯一的瓶颈是百度下载

其余环节都是分钟级，只有"把文件从百度网盘弄到本机"是以小时计的。这是账号级限速，**换机器、多线程、租大带宽服务器都没用**：

| 账号 | 实测速度 | 1GB 需要 | 来源 |
|---|---|---|---|
| 非会员 | 96–170 KB/s | 约 1.7–3 小时 | 澎湃新闻 2025-03 同机同网实测 8 款网盘 |
| 非会员 | ~50 KB/s（多连接实测相同） | 约 6 小时 | baidu-pan-skill 逆向实测 2026-09 |
| SVIP | 7–10 MB/s | 约 2 分钟 | 同上澎湃实测 |

所以：

- **要快，只有开 SVIP**（年卡常见价 ¥188 上下）。⚠️ 有说法是会员每月含 20G 极速流量，超出可能降速——批量下几十 GB 之前，先用一个文件试到触顶。
- 不想花钱也行，脚本支持断点续传，挂着跑就是了。10GB 大约两三天的挂机时间。
- 如果这些视频在 B站/YouTube 上也有，**优先用 yt-dlp 从那边拿**——那边不受账号限速，完全是另一个量级。

另外要说清楚：**没有"个人可用、不经过本机"的合法通道**。百度开放平台确实有"分享解析→转存→取下载地址"的接口，但官方写明是**企业开发者专属权益 + 付费能力**，个人申请不了。

### 所以，还有第三条路：根本不让脚本去下载

用**百度网盘客户端**（不是网页版）把视频下到本机——客户端通常能跑到 1MB/s 以上，实测比脚本走网页通道快得多——然后让本工具**直接读你本机上那个文件**：

```bash
python run.py local "D:\BaiduNetdiskDownload\某个文件夹"      # 扫描文件夹
python run.py local "D:\视频\第一集.mp4" "D:\视频\第二集.mp4"   # 直接点文件
```

网页界面里就是「③ 开始转写」下面那块「直接转本机上的文件」。这条路的好处：

- **完全不需要百度 Cookie**，不碰你的网盘账号，也就没有风控和限速问题；
- 不占网盘里的中转目录；
- 扫描文件夹的方式**不复制文件**，只是读路径；
- 只读不写：不移动、不改名、不删你的源文件（有断言钉着这一点）。

代价只有一个：文件得先在你自己机器上。

## 二、装好它

### 1. Python 环境

需要一个 Python 3.9+ 和一个 ffmpeg。

```bash
# 在 bpan2md 目录下
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
```

ffmpeg 没装的话：Windows 用 `winget install Gyan.FFmpeg`，macOS 用 `brew install ffmpeg`。

> 只需要 `requests` 一个第三方包。OSS 上传是脚本内自己实现的签名——官方的 `oss2` 依赖 `crcmod`，而 `crcmod` 在 Windows 上没有预编译包，装不上。

### 2. 百度网盘 Cookie

1. 浏览器登录 `pan.baidu.com`
2. 按 `F12` → **Network** 标签 → 刷新页面
3. 随便点一个请求 → **Request Headers** → 找到 `Cookie:` → 复制**整条值**
4. 粘到 `.env` 的 `BAIDU_COOKIE=` 后面

脚本会自动从里面挑出需要的几个（BDUSS / STOKEN / BAIDUID…）写进 `work/cookies.json`。**这个文件等于你的账号，用完请删掉。**

### 3. 转写服务的 Key

先复制配置文件：`copy .env.example .env`（macOS/Linux 用 `cp`）。

推荐组合（**百炼 + 阿里云 OSS**）：

```
ASR_BACKEND=bailian
DASHSCOPE_API_KEY=sk-你的百炼key
OSS_ENDPOINT=oss-cn-beijing.aliyuncs.com
OSS_BUCKET=你的桶名
OSS_AK_ID=你的AccessKeyId
OSS_AK_SECRET=你的AccessKeySecret
```

- 百炼 Key：阿里云百炼控制台 → API-KEY
- OSS：阿里云控制台建一个 Bucket（地域建议和百炼一致，比如都用北京），然后创建 AccessKey

### 4. 上线前预检

```bash
python run.py preflight
```

**不花钱、不使用你的真实 Key**，专门拦那些低级但致命的配置错误：

- ffmpeg / requests 在不在；
- 转写端点域名通不通；
- **OSS 的桶名和地域对不对**——这一步能真的查出问题。比如桶在别的地域时，它会直接告诉你该怎么改：

```
  ✗ OSS 桶地域不符：桶 mybucket 不在 oss-cn-beijing.aliyuncs.com，
    它属于 oss-cn-hangzhou.aliyuncs.com
      → 把 OSS_ENDPOINT 改成 oss-cn-hangzhou.aliyuncs.com
```

桶名写错会报 `NoSuchBucket`，端点拼错会报域名解析失败——都能一眼看出区别。

> 一个必须说清的边界：**百炼会先校验 Key 再路由**，所以拿无效 Key 打过去，正确路径和不存在的路径都返回 401。这意味着预检**只能证明网络和域名通，不能证明路径或参数写对了**——那要靠下一步的 doctor。

### 5. 云端体检

```bash
python run.py doctor
```

这一条**不需要百度账号**，它会合成一段 20 秒测试音频，把「上传 OSS → 检查公网能不能读到 → 提交转写 → 轮询 → 生成 Markdown」整条云端链路真跑一遍，并报出耗时和花费估算。

它专门解决一个很烦的问题：批量跑几小时后才发现 OSS 权限不对或 API Key 无效。提前一分钟验证掉。

其中「公网可达性检查」是特意加的——如果对象存储没开公共读、或者签名算错了，转写服务那边只会给一个含糊的失败；这里会直接告诉你是 403 还是 404。

想顺便验证**识别质量**（而不只是链路通不通），用你自己的音频：

```bash
python run.py doctor --audio 随便一段中文录音.mp3
```

## 三、开始用

顶层命令一览：

```
web        打开网页界面（推荐：不用敲命令，浏览器里点按钮）
check      检查配置和依赖（纯离线，不联网）
preflight  上线前预检：端点连通性、OSS 桶名与地域（不花钱、不用真 Key）
doctor     实时体检：用测试音频验证「上传→公网可达→转写→出稿」
inspect    列出分享里的文件，并预估转写费用
speedtest  实测下载速度，算出整份分享的耗时
run        跑完整流程（--dry-run / --limit / --only / --links / --speakers / --retry-hours）
local      直接转本机上的文件，不经过百度网盘（也不需要百度 Cookie）
index      生成知识库总目录 + 合并分块文件
render     由 result.json 重新生成 Markdown
clean      清理中间产物（--raw 连原片一起删，--uploads 连上传的原件一起删）
```

推荐顺序：

```bash
python run.py check          # 看还缺什么
python run.py preflight      # 预检配置形状和网络
python run.py doctor         # 不碰百度，先把云端链路真跑通
```

确认云端没问题之后，再开始处理百度那边：

```bash
# 先测速：确认这个账号当前到底多快，并算出整份分享要下多久
python run.py speedtest "https://pan.baidu.com/s/1xxxx?pwd=ab12"

# 只看计划、不下载不花钱（会告诉你总大小、预计耗时、预计转写费用）
python run.py run "https://pan.baidu.com/s/1xxxx?pwd=ab12" --dry-run

# 跑一个文件试试（--limit 1 只处理第一个顶层条目）
python run.py run "https://pan.baidu.com/s/1xxxx?pwd=ab12" --limit 1

# 跑通了，再批量
python run.py run --links links.txt
```

几点说明：

- **分享链接可以整段粘进去**，不用自己从里面挑出链接。网盘里点「分享」→「复制链接」之后拿到的那一整段（含文件名、「链接:」、「提取码:」这些套话）原样贴进去就行——网页里粘完会立刻显示"认出了几个链接、提取码是多少、文件名是什么"，点开始之前就知道自己贴对了没有。
- `speedtest` 会把实测速度记进状态文件，之后 `run` 开跑前会**自动给出真实耗时预估**，方便你在开始一次几十小时的下载之前先想清楚。
- **`--limit` 数的是顶层条目**，文件夹算一个。百度分享经常是「一个文件夹里几十个视频」，脚本会把文件夹整个转存下来再展开处理。
- `--limit 1` 试跑之后改成批量**没问题**：脚本发现选择参数变了会重新解析分享并合并新增文件，不会漏掉剩下的。
- `--limit` 变大时，已经下好的文件不会重下。
- **中断了就直接重跑同一条命令**，已下载的不重下、已转写的不重花钱。

### 不让脚本下载：直接转本机文件

```bash
# 扫描整个文件夹（含子目录），把里面的音视频都转掉
python run.py local "D:\BaiduNetdiskDownload\某个文件夹"

# 只看计划：读一遍时长、报出花费，不抽音频、不上传、不花钱
python run.py local "D:\视频" --dry-run

# 直接点几个文件，或者只处理前 2 个
python run.py local "D:\视频\第一集.mp4" "D:\视频\第二集.mp4"
python run.py local "D:\视频" --limit 2

# 不想进子目录 / 确定都是单人
python run.py local "D:\视频" --shallow --speakers single
```

网页界面里就是「③ 开始转写」下面那块：粘贴文件夹路径 → 扫描 → 勾选 → 加进清单 → 开始转写；
也可以把文件**拖进那个虚线框**（或者点它选文件），那样会复制一份到 `work/uploads`。

- **不需要百度 Cookie**：这条路完全不碰网盘，`check` 也只检查云端转写要用的东西；
- **不复制、不移动、不改名、不删你的源文件**（有断言钉住"源文件的大小和修改时间跑完没变"）；
- 中间产物（抽出的音频）放在工具自己的 `work/audio` 里，界面上有按钮可以一键清掉；
- 同一个文件重复跑会命中缓存不会重复花钱；但如果**同名文件被换成了另一份内容**，
  会检测出来并重新转写（否则会静默地给你一份对不上的旧稿子）。

跑完会打印一份批量汇总：

```
批量汇总
  文件：12 个　成功 11　失败 1　待续 0
  已下载 3.4 GB，音频总时长 9.83 小时
  转写花费估算：约 7.79 元（在 10 小时免费额度内，可能不花钱）
```

### 挂机模式（推荐用于大批量）

按前面的实测，非会员下 10GB 要两三天。这两三天里几乎一定会遇到网络抖动、Cookie 过期、百度风控——让你盯着屏幕手动重跑不现实。所以有监督模式：

```bash
python run.py run --links links.txt --retry-hours 72 --retry-interval 20
```

- 在这 72 小时内**反复重试**，直到全部完成或超出预算；
- 每轮之间**重新读一次 `.env`**——所以你挂机期间发现 Cookie 失效，只要更新 `BAIDU_COOKIE`，**下一轮就会自动接上，不用重启进程**；
- 已下载的不重下、已转写的不重花钱；
- 每一轮都会打印时间戳，方便你回来看进展。

先跑一次不带 `--retry-hours` 的普通模式确认能跑通，再加这个参数过夜。

---

`links.txt` 每行一个链接，支持四种写法（也可以直接把整段复制内容贴进去）：

```
通过网盘分享的文件：《某讲座》01.mp4
链接: https://pan.baidu.com/s/1AAA?pwd=ab12 提取码: ab12 复制这段内容后打开百度网盘手机App，操作更方便哦

https://pan.baidu.com/s/1BBB | cd34
https://pan.baidu.com/s/1CCC
```

## 四、选哪个转写服务

| 后端 / 模型 | 价格 | 说话人分离 | 要公网托管吗 |
|---|---|---|---|
| 百炼 `paraformer-v2` | 0.00008 元/秒 ≈ **0.288 元/小时** | **✅ 支持** | 要 |
| 百炼 `fun-asr` | 0.00022 元/秒 ≈ **0.792 元/小时** | ✅ 支持 | 要 |
| 百炼 `qwen3-asr-flash-filetrans` | 0.00022 元/秒 ≈ 0.792 元/小时 | ❌ 不支持 | 要 |
| 百炼 `qwen-audio-3.1-asr-flash-filetrans` | 按 token 计费 | ✅ 支持 | 要 |
| 通义听悟 | **0.60 元/小时**（含说话人分离） | ✅ 支持 | 要 |
| 硅基流动 `SenseVoiceSmall` 等 | **免费**（官方价格页） | 部分模型支持 | **不要** |
| Groq `whisper-large-v3-turbo` | ≈0.28 元/小时 | ✗ | 不要（直传，但单文件 25MB） |

> ⚠️ **一个容易搞反的点**：说话人分离**不是加价项**，计费只按音频秒数。
> 最便宜的 `paraformer-v2` 本身就支持分离（官方能力表原文：
> 「paraformer-v2　HTTP 录音文件识别，**支持说话人分离**，中、英、日、韩、德、法、俄」）。
> 所以**不需要**"单说话人用便宜模型、多说话人用贵模型"——直接用
> `paraformer-v2` + `BAILIAN_DIARIZATION=true` 就是又便宜又有分离。
> 本项目早先的说明在这里写错过，已更正。

免费额度：百炼录音文件识别每月 36000 秒（10 小时）；通义听悟试用 90 天、每天 2 小时。

**怎么选：**

- 想省事、不想配 OSS → `ASR_BACKEND=siliconflow`（免费，但结果没有逐句时间戳，Markdown 会退化成按标点分段）
- 要区分说话人、又要最便宜 → `bailian` + `paraformer-v2` + `BAILIAN_DIARIZATION=true`
- 要最好的识别质量（多方言、热词）→ `bailian` + `fun-asr` 或 `qwen-audio-3.1-asr-flash-filetrans`

> 代码里维护了一张模型能力与价格登记表（`bp2md/models.py`），启动时会校验你选的模型
> 是否支持分离、是不是文件转写模型，并在 `python run.py check` 里显示价格和能力。
> 选错不会静默失效——传错参数名导致"设置了分离但其实没生效"是最难查的失败，已经堵住。

### 跑之前先看价钱

下载任何东西之前就能看到预计花费——百度分享页的数据块里带了时长：

```bash
python run.py inspect "https://pan.baidu.com/s/1xxxx?pwd=ab12"
# ...
# 预计转写：1.50 小时音频 ≈ 0.43 元（paraformer-v2），在每月 10 小时免费额度内
```

`--dry-run` 也会打印同样的预估。文件夹分享拿不到里面文件的时长，这种情况会明说
"分享里没有时长信息，无法预估"，不会给你一个假数字。

### 单人还是多人？不用预先探测

既然分离不是加价项，就**不需要**"先判断有几个说话人，再决定用哪个 API"——那套做法只会多花一次检测的钱。

真正需要区分单/多的地方是**输出形态**，而这个可以零成本解决：分离开启时结果里本来就带 `speaker_id`，**数一下就有答案**。

所以自动行为是：

- **只出现一个说话人** → 正文不渲染「发言人 1：」前缀（整篇刷同一个前缀对知识库毫无增益），前端元数据里仍然记着 `speaker_count: 1`；
- **出现两个及以上** → 正文按 `**[00:00:03] 发言人 1：** 正文…` 标注；
- `index.json` 里每条都带 `single_speaker` 布尔值，知识库可以直接筛。

想手动控制就用 `--speakers`：

```bash
python run.py run --links links.txt --speakers single   # 确定都是单人：关掉分离
python run.py run --links links.txt --speakers auto     # 默认：按结果自动
python run.py run --links links.txt --speakers multi    # 强制开启分离
```

`--speakers single` 除了让输出更干净，还有个附带好处：单段上限不必收紧到 2 小时，
**切片更少、API 调用次数更少**（总价不变，但更省事）。

> ⚠️ 一个容易忽略的限制：**分段转写的说话人编号只在段内有效**。如果一份素材超过 2 小时被切成几段分别转写，
> 「发言人 1」在第一段和第三段未必是同一个人。脚本会在正文顶部明确标注这一点，
> 并在 front matter 里写 `parts: N`。要跨段对齐说话人需要额外的声纹聚类，目前没做。

改了 `--speakers` 之后重跑，脚本会识别出分离设置变了、**清掉缓存的结果重新转写**
（会重新计费，日志里会说明），而不是拿旧参数的结果糊弄过去。

> ⚠️ `siliconflow` 后端按 OpenAI 兼容的 `/v1/audio/transcriptions`（multipart 直传）实现。
> **接口路径已实测核对过**：该网关先路由再鉴权，所以拿占位 Key 打过去时，
> 正确路径返回 `401 Token is invalid`、错误路径返回 `404 Not Found`——`preflight` 就是靠这个区分
> （它会告诉你 `SILICONFLOW_BASE` 写没写对）。
> 但**请求参数（model 名、返回字段名）仍未经真实 Key 验证**，因为它的文档站是 JS 渲染的、抓不到参数表。
> 建议第一次拿一个几十秒的小文件试跑。

## 五、输出长什么样

每个音视频产出三个文件：

```
output/
  讲座第一节.md              ← 给知识库的正文
  讲座第一节.chunks.jsonl    ← 分块，直接喂向量库
  讲座第一节.result.json     ← 原始结果，改排版时不用重新转写
```

`讲座第一节.md` 开头是 YAML 元数据（Obsidian / Logseq / 思源 都能识别）：

```markdown
---
title: "讲座第一节"
source_file: "讲座第一节.mp4"
source_url: "https://pan.baidu.com/s/1xxxx?pwd=ab12"
duration: "01:23:45"
duration_seconds: 5025
transcribed_at: "2026-10-05T14:30:00+08:00"
asr_backend: "bailian"
asr_model: "paraformer-v2"
speaker_diarization: true
speaker_count: 2
speakers: ["0", "1"]
speaker_labels: true
tags: [转写稿, 音视频]
---

# 讲座第一节

> 来源文件：讲座第一节.mp4　｜　时长 01:23:45　｜　转写：bailian/...

## 00:00:00 – 00:10:00

**[00:00:03] 发言人 0：** 大家好，今天我们讨论三个问题。

**[00:00:12] 发言人 1：** 我先说一下背景。
```

正文按 **10 分钟一个 H2** 切小节，每句独立成段并带 `[hh:mm:ss]` 前缀——检索命中后能直接告诉你"哪个文件、第几分钟、谁说的"。

`chunks.jsonl` 每行一块，已经按语义边界切好（说话人切换、超过 8 秒停顿、或达到 ~500 字就断块）：

```json
{"doc_id":"讲座第一节","chunk_id":0,"title":"讲座第一节",
 "source_file":"讲座第一节.mp4","source_url":"https://pan.baidu.com/s/1xxxx",
 "start":"00:00:03","end":"00:01:12","start_ms":3000,"end_ms":72000,
 "speakers":["0"],"text":"大家好，今天我们讨论三个问题。……","char_count":486}
```

入库时直接读 `text` 做向量，把 `title` / `start` / `source_url` 存成元数据即可。

### 攒多了一起入知识库

```bash
python run.py index
```

扫描 `output/` 生成两个文件：

- `index.json` —— 所有文档的清单（标题、来源、时长、说话人数、是否单人、字数、分块数、对应 Markdown 文件名），可以直接拿来当知识库的目录树；
- `all.chunks.jsonl` —— 所有文档的分块**合并成一个文件**，向量库入库时一次读完，不用自己遍历目录拼接。

```bash

    · 讲座第一节　01:23:45　42 块　2 位说话人
    ...
```

## 六、常见问题

**Cookie 失效**（报 `-6` / `31045` / `loginstate`）
重新复制一次 Cookie 到 `.env`，删掉 `work/cookies.json`，再跑。

**百度要验证码**
脚本会提示 `captcha`。用浏览器打开一次那个分享链接，通过验证后再跑。

**触发风控**（`errno 132` / `9013`）
说明这个账号当前被限制了。停一会儿，先在网页端正常操作一次再继续。别短时间高频抓取。

**网盘里多了一个 `bpan2md_中转` 目录**
正常。下载通道只认你自己网盘里的路径，所以文件要先转存进来。每个分享会在里面建一个以分享 ID 命名的子目录，方便你在客户端里整个删掉。

**下载慢得离谱**
正常，就是账号限速。看看 `speedtest` 的数字，决定是开 SVIP 还是挂机。

**超过单段上限**
脚本会自动切：先抽音频，再按 `MAX_SEGMENT_SECONDS` 切段，转完自动按偏移拼回整段的时间轴。默认 6 小时（兼容听悟的 6G/6h 限制）；用百炼可以把 `MAX_SEGMENT_SECONDS` 调到 43200（12 小时）。开了说话人分离时会自动收紧到 2 小时。

**上传 OSS 失败**
先看是不是 AK/SK 或桶名错了（403 通常是签名/AK 问题）。`OSS_PUBLIC_READ=true` 最省事；如果你不想公开，设成 `false`，脚本会生成有效期 7 天的签名 URL。

**改了排版想重新生成**
```bash
python run.py render output/讲座第一节.result.json
```
不用重新转写、不用再花钱。它会更新原来那个文件，不会另建一个新的。

**手滑删了 Markdown**
再跑一次 `run` 就会自动补回来——脚本会检查产物是否还在，不在就用已保存的 `result.json` 重新渲染，不会重下也不会重新转写。

**下载不完整 / 文件损坏**
每次下载完都会核对文件大小和时长（时长对不上会警告，大小对不上会直接报错）。如果本地文件被截断，重跑时会被自动识别并重新下载。

**分享里是个文件夹**
支持。脚本会把整个文件夹转存下来再展开，只挑音视频，跳过里面混着的 txt/图片；嵌套目录里的同名文件也不会互相覆盖（输出文件名会带上目录前缀）。

**想省磁盘**
```bash
python run.py clean             # 删音频和切片，保留原视频
python run.py clean --raw       # 连下载的原视频一起删
python run.py clean --raw --uploads   # 连网页上传进来的原件一起删（那是你自己的文件）
```
`clean` 之后继续跑也不会出问题：脚本发现音频不在了会重新生成（原视频还在的话不必重下）。
网页界面里是「④ 结果」下面那张「磁盘占用与清理」表，能先看到每一类各占多少再决定。

**`work` 目录里的原视频和音频是干什么的？能删吗？**

那是**中间文件**，不是垃圾，也不是必须留的东西：

| 目录 | 是什么 | 为什么留着 |
|---|---|---|
| `work/raw/` | 从网盘下下来的原视频 | 重跑时（换模型、改说话人设置、上次失败）不用再花几小时重下 |
| `work/audio/` | 抽出来的 mp3（真正被上传和计费的东西） | 重跑时不用重新跑 ffmpeg |
| `work/segments/` | 超过单段上限时的切片 | 同上 |
| `work/uploads/` | 网页里「拖进来」上传时的副本 | 只有这一种方式会复制文件（扫描文件夹不会） |
| `work/state/` | **进度账本：哪些文件已经花钱转写过了** | **不能删**——删了下次会把所有文件当新的重新下载 + 重新计费 |
| `work/cookies.json` | 百度登录凭据 | 可以用完就删；下次会自动从 `.env` 重建 |

所以清理时**要连 `work/state` 一起删就错了**。用提供好的入口删（命令行 `clean`，或网页里那个按钮），它删的是"能重新算出来的"，留的是"算了要花钱的"。

已经出稿的文件即使中间文件被清掉也不会重新下载、不会重新计费——账本记着它的产物在 `output/` 的哪里。只有当你主动要重做某个文件时，才需要原片重新在场。

其中 ASR 客户端那一组值得一提：`bp2md/asr.py` 里的提交/轮询/取结果/解析逻辑，此前**从未被真正执行过**（流水线测试都在 `make_asr` 那层就打桩了）。现在用 `tests/mock_asr.py` 起一个本地 HTTP 服务，让它走完整的真实网络请求，返回的报文结构逐字段照抄官方文档。于是这些都被真正跑到了：

- 提交请求的头（`X-DashScope-Async: enable`）与体（`model` / `file_urls` / `language_hints`）；
- 轮询的状态流转（RUNNING → SUCCEEDED），以及任务失败、子任务失败、缺 `transcription_url`、缺 `task_id` 四种错误路径；
- **结果解析**——`transcripts[].sentences[]` 里的 `begin_time`/`end_time`（毫秒）与 `speaker_id`，也就是最初那份方案错得最离谱的地方；
- 提交与轮询遇到 5xx 时的退避重试确实接上了；
- 结果 JSON 缺字段时不崩。

另外它会顺带跑 **vendored 百度层自带的上游测试**（46 项通过、3 项因缺 `openssl` 而跳过）。这层代码是从上游拷来的、长期被当黑盒使用；上游自带测试恰好覆盖了我们最依赖的几处行为——分享页 `locals.mset` 解析、**文件夹分享的递归转存**、断点续传与短读重试、**凭证失效时的快速失败**、`relpath` 目录树生成。来源、改动和升级方式记在 [`vendor/baidu_pan/PROVENANCE.md`](vendor/baidu_pan/PROVENANCE.md)。

其中两条是安全/正确性不变量，值得单独说：

- **预检绝不发送真实 API Key**（用占位 Key 探测，避免"体检"变成"误建任务并计费"）；
- **提交转写任务的连接错误不重试**（响应丢了不代表任务没创建，盲目重试会重复计费）。

流水线部分专门盯住几条容易悄悄坏掉的路径（都带回归测试）：

- 换 `--limit` 重跑时必须重新解析分享，且已下好的文件不能重下；
- 文件夹分享要能展开、要跳过非音视频、嵌套同名文件不能互相覆盖；
- `--dry-run` 绝不能触发下载或转写；
- 本地文件被截断时要重新下载，产物被删时要能重新生成；
- 改 `--speakers` 时必须清掉旧结果重新转写（不能因为"已完成"就静默跳过）。

还有一组**文档与代码一致性**断言，专门防"说明写错了但没人发现"：

- `.env.example` 里声明的每个键都必须真的被 `config.py` 读取（反过来也一样：代码在读的键必须有文档）；
- 上面那段 front matter 示例里的**每个字段都必须真的会被产出**；
- 命令一览必须和 argparse 的子命令完全一致；
- 这里的验证项数不能和实际差太多。

> 为什么要专门加这一组：本项目真实踩过——成本表一度把 `paraformer-v2` 标成
> "不支持说话人分离"，而它其实支持。这条错误信息直接导致"单/多说话人要用不同 API"
> 这个**错误前提**。文档说错话的代价，和代码写错是一样的。

### 网页界面的专项验证

后端 API 测试全绿**不代表网页能用**——JS 有语法错误或按钮 id 写错，页面就是白屏或点了没反应。所以另外做了两层：

**`tests/ui_audit.py`（静态，不需要跑服务）**：用真正的 JS 解析器（`node --check`）检查语法；交叉核对 JS 里引用的每个元素 id 是否真的存在；核对页面调用的每个 `/api` 地址后端是否注册；检查 HTML 标签闭合与关键控件是否齐全。

**`tests/browser_check.py`（真实浏览器，推荐）**：用 Playwright 驱动系统上已有的 Chromium/Edge 真打开页面，把「粘贴识别 → 扫描文件夹 → 加进清单 → 上传文件 → 只看计划 → 清理中间文件」真的点一遍，同时收集 `console.error`、页面异常、失败请求，并把每一步截图存到 `.selftest-tmp/browser/`。

```bash
python tests/browser_check.py            # 无头
python tests/browser_check.py --headed   # 弹出真窗口，自己看着它点
```

它抓的是静态审查永远抓不到的东西——布局把按钮盖住了（真抓到过一次：底部日志面板浮在内容上，把「只处理前几个」那块挡掉了）、某个 id 其实选不中、接口返回的结构和前端期待的对不上。全程只做离线动作，用的是临时 `.env` 和临时工作目录，**不会连百度、不会连阿里云、不花钱**。

**`tests/adversarial_ui.py`（动态，对运行中的服务做真请求）**：按浏览器的操作顺序把每个按钮点一遍，并故意喂坏输入——空链接、乱链接、非法 JSON、超大请求体、非对象请求体、非数字的任务编号、路径穿越（含 URL 编码和绝对路径形式）、并发起两个任务、点了停止之后再起任务、含中文和空格的配置值往返。

这几层各自抓到过真问题：

- **一个 300 万字符的 Cookie 被写进 `.env`，把整个服务搞死了。** Windows 环境变量单个值上限是 32767，之后每次读配置都抛 `ValueError`，所有请求 500，而用户完全不知道该删哪一行。现在超长值会被拒绝并给出人话，而且**即使 `.env` 里已经有一个坏值，程序也照常启动**，只在 `check` 里报"这个键太长、怎么修"。
- **拒绝超大请求时没读请求体，导致客户端连接被中止。** HTTP/1.1 下服务端不读 body 就回响应，客户端还在写，会收到 RST——在浏览器里表现成"点提交没反应"。现在会先把 body 读掉（有上限）再回 413。
- **点「云端链路体检」日志一片空白。** `doctor` 是写给终端看的、用 `print` 输出，而网页只收 `log` 回调——不做 stdout 重定向，用户点完什么都看不到。`preflight` 当时重定向了，`doctor` 漏了。
- **配置在进程里"粘住"。** 原先把 `.env` 的值注入 `os.environ`，导致配置具有全局副作用：测试里一个真实存在的 `.env` 让"什么都没配"的用例读到了 Cookie 和 API Key；同类问题也会让别的代码隔空拿到不该拿的值。现在**不再注入**，`.env` 的值直接进配置对象——真实环境变量依然优先，改完文件下次读取依然生效，但不再有全局状态。顺带删掉了为绕开这个副作用而加的 `_INJECTED_FROM_ENV` 全局变量。
- **底部日志面板把内容盖住了。** 日志原来是 `position:sticky`，浮在页面上——加了「本地文件」那一大块之后，它把「只处理前几个」「说话人处理」这些控件整个挡住了。改成"上面滚动的内容区 + 下面固定的日志区"的竖排布局，并且**让浏览器自己跑一遍截图确认**才发现（静态审查看不出这个）。
- **一个"看机器脸色"的自检。** 自检最后有一条"README 里的项数要和实际一致"，而其中一项（跑上游测试）在没装 pytest 时会直接 `return`，于是**同一份代码在一台机器上全绿、在另一台上莫名变红**。现在那一项无条件记录结果，缺 pytest 会明确报出来并给出安装命令。
- **让浏览器读取本地路径相关的接口必须自己防跨站。** 服务能读本机文件、能花钱，而浏览器不拦网页向 `127.0.0.1:8765` 发请求（DNS rebinding 更是能让恶意域名直接解析到本机）。现在校验 `Host` 与 `Origin`：非本机来源一律 403，同名主机的正常页面照常工作。

**云端那半段用 `python run.py doctor` 自证**——它不需要百度账号，把上传、公网可达、提交、轮询、结果解析、出稿全跑一遍。跑之前请务必先做这一步。

**仍然只能用你的账号验证的**：百度那边的分享解析、转存、下载（需要登录态），以及真实长音频的识别质量。

所以第一步请务必用 `--limit 1` 拿一个小文件跑通，再批量。

### 验证边界的一张表

| 事项 | 怎么验证 | 花钱吗 |
|---|---|---|
| 代码逻辑、断点续跑、输出格式 | `tests/selftest.py`（476 项，全离线打桩） | 否 |
| **网页界面本身能不能用** | `tests/browser_check.py`（真浏览器点一遍 + 截图） | 否 |
| **百度下载层本身**（分享页解析、转存、续传、`relpath`） | 上游自带的 46 项测试，已接进自检 | 否 |
| 网络、端点域名、**OSS 桶名与地域** | `run.py preflight` | 否 |
| **硅基流动的转写路径**（401 表示路径对、404 表示路径错） | `run.py preflight` | 否 |
| Key 有效、模型名对、参数对、结果解析 | `run.py doctor`（真跑一段 20 秒音频） | 约 0.001 元 |
| 百度分享的真实解析/转存/下载、真实识别质量 | 只能你自己跑 | 视百度账号 |

关于第五行要坦白一点：**百炼先校验 Key 再路由**，所以预检阶段无法判断路径和参数是否正确（无效 Key 下任何路径都返回 401）。这一项只有 `doctor` 用真 Key 才能确认——这也是为什么建议在批量之前一定要跑一次 doctor。

### 顺带说下健壮性

批量跑几小时最容易死在"一次瞬时 5xx 或连接重置"上，所以 HTTP 层做了区分：

- **幂等请求**（查询任务状态、下载结果、上传对象）连接错误和 5xx 都会退避重试；
- **有副作用的请求**（提交转写任务）只对明确的 429/5xx 重试，**连接错误直接抛出**——因为响应丢了不代表任务没创建，盲目重试会重复计费；
- 轮询期间网络抖动会容忍连续 10 次失败才放弃，避免几小时的任务前功尽弃。

### 挂机几十小时才会遇到的情况

这些都是"跑到一半才出问题"的类型，已经专门处理过：

**登录态失效 → 立刻中止整个批量。** 百度 Cookie 会过期。以前的表现是：剩下的每个文件挨个失败，刷一屏错误，看起来像"这批文件都有问题"，还白占几小时。现在一旦识别出是登录态问题，马上停下来并告诉你怎么做：

```
!! 已中止整个批量：百度登录态已失效。
→ 重新从浏览器复制 Cookie 更新 .env 的 BAIDU_COOKIE，删掉 work/cookies.json，
  然后重跑同一条命令即可续上已下载的进度。
```

触发风控（errno 132 / 9013）和要求验证码也走同一条路径——都需要人工介入，继续跑没有意义。

**磁盘空间。** 开跑前先看可用空间，不够就直接报错（而不是写到一半失败）；偏紧会提醒你。批量下几十 GB 时这个提醒很有用。

**文件没有音轨。** 有些分享出来的是无声录屏或纯图片视频。以前会甩给你一段难懂的 ffmpeg 报错，现在直接说"这个文件没有音轨，无法转写"。多音轨会提示只转写第一条。

**说话人分离的 2 小时上限。** 阿里云官方明确建议：启用说话人分离时单段不超过 2 小时，否则可能识别失败或超时。所以打开 `BAILIAN_DIARIZATION` 后，单段上限会**自动收紧到 2 小时**（即使 `MAX_SEGMENT_SECONDS` 配的是 6 小时），并在日志里说明原因——否则长录音会以失败告终，而错误信息完全指不到真正的原因。
